How it works

What the validator checks

Every annotation becomes an edge from a page to one of its alternates. All edges go into one graph, so the tool can see each complete page set, which the matrix view calls a cluster, and check it as a whole instead of row by row.

  • Invalid codes. Language must be ISO 639-1, region ISO 3166-1 alpha-2, with an optional script like zh-Hant. Common mistakes come with a suggested fix.
  • Missing return links. If page A lists page B, B must list A. Google ignores pairs that don't confirm each other. The finding names the page that has to add the link, and points out near misses like /en versus /en/.
  • Conflicting targets. One page sending the same code, or several x-defaults, to different URLs.
  • Inconsistent mapping. Pages in the same set disagreeing about which URL is which language, or one URL labelled as two different languages.
  • Missing self-references. A page that lists its alternates but not itself.
  • Page language mismatch. When the file has a page language column, it is checked against the code the annotations use for that page.
  • Relative and HTTP URLs. hreflang needs fully qualified URLs, and an HTTP alternate on an HTTPS site usually points to a redirect.
  • Targets with no data and page sets without x-default, reported so they are deliberate rather than accidental.

The page set matrix

A findings list tells you what is wrong. The matrix shows you where. Each page set gets a grid: pages down the side, hreflang codes across the top. A complete, healthy set is a solid block of ticks. A missing return link, a wrong URL or a hole in the set stands out immediately, and hovering a cell shows the exact URL and the reason.

For each code, the expected URL is the one most pages in the set agree on, with a page's own self-reference as the tie-breaker. That is also how the clean exports are built.

Language and region codes

Supported layouts

One row per annotation

The most common audit format: page URL, hreflang code, alternate URL. A page language column is optional and gets its own check. Columns are recognised from their values, so the headers can say anything.

Matrix

The format most migration plans and translation trackers use: each row is one piece of content, each column header is an hreflang code, each cell is the URL for that version. Every URL in a row is assumed to carry the full set of annotations for that row, which is exactly what the implementation should produce.

Screaming Frog

Export Hreflang › All. Address becomes the page and every HTML hreflang N and HTML hreflang N URL pair becomes one annotation. Sitemap hreflang columns from a sitemap crawl are read the same way.

XML sitemap

Paste or upload a sitemap that uses xhtml:link rel="alternate". Each <loc> is a page and each link one of its annotations. Sitemap index files are not followed, so load the child sitemap that holds the hreflang entries.

What this tool does not do

It validates annotations, not the live site. It does not request any URL, so it cannot see whether an alternate redirects, returns a 404, is noindexed or canonicalises somewhere else. Google ignores hreflang to any of those. Crawl the URLs in your export with Screaming Frog, check status and canonicals, then run the Hreflang › All export through this validator.

FAQ

Is my file uploaded anywhere?

No. The file is read and processed by JavaScript in your browser. Nothing is sent to a server, so unreleased URL structures and client data stay private.

Which Screaming Frog export should I use?

Crawl the site with hreflang extraction enabled, open the Hreflang tab and export All. Address becomes the page, and every HTML hreflang N and HTML hreflang N URL pair becomes one annotation. Sitemap hreflang columns work the same way.

Is a missing self-reference an error?

Google's documentation asks every language version to list itself as well as all other versions. In practice a missing self-reference rarely breaks a cluster on its own, so the validator reports it as a warning rather than an error.

Do I need x-default?

No, it is optional. It tells search engines which URL to show users whose language or region matches none of your versions, usually a language selector or the main international page. The validator lists page sets without one as a notice.

Can one URL be used for several hreflang codes?

Yes, as long as it is the same language. One English page can serve en, en-GB and en-IE. The validator only flags a URL that is assigned two different languages, such as de and fr.

Does it check canonicals and status codes?

No. It validates the annotations in the file and does not request any URL. Hreflang pointing to redirected, non-200 or canonicalised URLs is ignored by Google, so crawl the URLs in the export as well before launch.
