How it works

What the validator checks

Every row becomes a set of steps: source, any hops, then the target. All steps from the whole file go into one redirect graph, so a problem is found even when it spans several rows.

  • Chains. A source that needs two or more hops to reach its final URL, whether the hops sit in one row or in different rows.
  • Loops. URLs that redirect back to themselves through one or more steps, including loops closed across separate rows.
  • Conflicts. The same URL sent to two different destinations. Only one can win on the server, and it is rarely the one you expect.
  • Duplicates. The same redirect listed twice. Harmless, but a sign the sheet needs a cleanup.
  • Self-redirects. A source that points to itself.
  • Missing or malformed values. Empty cells, notes typed into a URL column, broken URLs.
  • Temporary redirects. 302, 303 or 307 status codes, when the file has a redirect status column.
  • Final URL not 200. Chains that end on a 404 or another error, when the file has a final status column.
  • HTTPS to HTTP steps and targets on another host, flagged so they are deliberate rather than accidental.

Column roles instead of column names

Redirect maps arrive in every shape: a two-column migration sheet, a client's Excel file with notes, a chain export with Redirect URL 1, 2 and 3, a raw crawler export. Instead of asking you to rename headers, the tool looks at the values. Columns full of URLs or paths become the source, hops and target. Columns of three-digit numbers become status codes. Everything else is ignored.

You can override any column in step 02. Hops are read from left to right, and the target always comes last, so a layout like Address, Final Address, Redirect 1, Redirect 2 still gives the right path.

Formats that work as-is

  • Screaming Frog Response Codes › Redirection (3xx) export: Address becomes the source, Redirect URL the target, Status Code the redirect status.
  • Chain sheets with several redirect columns and a final URL column, including dashes in empty cells.
  • Relative paths such as /old-page/, matched against full URLs through the site URL setting.
  • Comma, semicolon and tab separated files. Excel on European locale settings saves CSV with semicolons, and that works too.

Why flatten redirect chains

Each extra hop is another request before the page loads, for users and for crawlers. Google documents that its crawlers follow a limited number of redirect hops, and long chains left over from older migrations waste crawl activity on URLs that should resolve in one step.

The flattened export fixes this at the source. Every URL that redirects, including the intermediate hops, points straight to its final destination. If /old-page/ went through /page-1/ and /page-2/, all three now go directly to /new-page/.

When to use the normalization options

By default /page and /page/ are different URLs, because on most servers they are. Turn on trailing slash, protocol, www or letter case matching only when your server already treats those versions as one URL, for example when a global rule adds the trailing slash. With matching on, a row like /category/seo → /category/seo/ is reported as a self-redirect, because the global rule already handles it.

What this tool does not do

It validates the map, not the live site. It does not request any URL, so it cannot see redirects your server adds on its own, such as HTTP to HTTPS or trailing slash rules. Once the redirects are live, crawl the old URLs in Screaming Frog list mode with redirects followed, and run the export through this validator again.

FAQ

Is my CSV uploaded anywhere?

No. The file is read and processed by JavaScript in your browser. Nothing is sent to a server, so client redirect maps stay private.

Which Screaming Frog exports work?

Response Codes › Redirection (3xx) works as-is: Address is the source, Redirect URL the target and Status Code the redirect status. Chain reports with several redirect columns work too. Check the column roles in step 02 and adjust anything that was guessed wrong.

Do I need to rename my columns?

No. Roles are detected from the values in each column, not from the header text. You can change any role with the dropdown above the column.

How are relative paths handled?

Paths such as /old-page/ are resolved against the site URL you enter, or against the first full URL found in the file. That way /old-page/ and https://example.com/old-page/ are recognised as the same URL.

How many rows can it handle?

Tens of thousands of rows run in well under a second in a modern browser. The results table shows the first rows and loads more on demand. Exports always include every row.

Why does the Apache export use RedirectMatch instead of Redirect?

Apache's Redirect directive matches by prefix, so a rule for /old would also catch /old-anything. The export uses anchored RedirectMatch rules so each rule matches exactly one URL. Sources with query strings are listed as comments, because they need a RewriteCond rule.
