Guide

What a good sitemap looks like

A sitemap is a list of the URLs you want search engines to index, and nothing else. Every entry should be canonical, return 200, be indexable, and use the same protocol and host as the rest of the site. Search engines treat the sitemap as a hint, so a list full of redirects, parameters and duplicates teaches them to trust it less.

What the analyzer checks

The files

  • XML validity, with the line and column of the first error. An unescaped & in a URL is the most common cause.
  • Root element and namespace. Exactly http://www.sitemaps.org/schemas/sitemap/0.9, not https and not an old Google namespace.
  • Encoding, which must be UTF-8.
  • Size limits for URLs and bytes, with an early warning from 45,000 URLs.

The URLs

  • Missing, relative, malformed and over-long URLs. Anything a crawler cannot fetch as written.
  • Duplicates across all loaded files, and near duplicates that differ only by trailing slash or letter case.
  • Mixed hosts and protocols. www next to non-www, HTTP next to HTTPS, and URLs on other domains.
  • URLs that rarely belong in a sitemap: tracking and session parameters, cart, checkout, account, search, feeds, pagination, tag and author archives, and static files like images or PDFs listed as pages.

lastmod, priority and changefreq

Google ignores priority and changefreq. It does use lastmod, but only when it is consistently and verifiably accurate. The analyzer flags invalid W3C Datetime values (a space instead of T is the classic one), dates in the future, and files where nearly every URL has the same date, which usually means the generator stamps the build time rather than the content change.

Sitemap indexes

Load the index together with its child sitemaps and the analyzer matches them by file name. It reports listed sitemaps you have not loaded, loaded sitemaps the index does not mention, indexes that point to other indexes, and children whose index lastmod is older than the newest URL inside them.

Compare the sitemap with a crawl

The most useful sitemap audit is a comparison. Crawl the site, filter to indexable HTML pages, and paste those URLs into the compare tab. Missing from sitemap shows real pages the sitemap forgot, often whole sections added after the generator was configured. Only in sitemap shows URLs the crawl did not find as indexable: redirected, noindexed, canonicalised or orphaned pages that should be fixed or removed.

What this tool does not do

It does not fetch anything. It cannot follow sitemap URLs from robots.txt, download child sitemaps or see status codes. That is deliberate: it works on staging files, client exports and sitemaps behind a login, and nothing leaves your browser. For live checks, crawl the sitemap URLs in Screaming Frog list mode and bring the results back here as a URL list.

FAQ

Are my sitemaps uploaded anywhere?

No. Files are read, unzipped and analysed by JavaScript in your browser. Nothing is sent to a server.

How do I check a sitemap index and its child sitemaps?

Load the index and the child sitemaps together, as several files in one drop. The analyzer matches children to the index by file name, checks every URL across all of them, and tells you which listed sitemaps are missing and which loaded files are not in the index.

Does Google use priority and changefreq?

No. Google ignores both. It uses lastmod, but only when the dates are consistently and verifiably accurate, so a sitemap where every URL has today's date is effectively a sitemap without lastmod.

What are the sitemap size limits?

One sitemap can hold up to 50,000 URLs and be up to 50 MB uncompressed. Larger sets are split into several sitemaps listed in a sitemap index, which has the same 50,000 entry limit.

Why compare the sitemap with a crawl?

A sitemap should list every indexable, canonical URL you want in search, and nothing else. Comparing it with the indexable URLs from a crawl shows important pages the sitemap forgot and stale or non-canonical URLs it still lists.

Does it check whether the URLs return 200?

No. It analyses the files and does not request any URL. To check status codes, canonicals and noindex, crawl the sitemap URLs with Screaming Frog in list mode, then compare the indexable URLs with the sitemap here.
